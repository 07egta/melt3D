# Melt3D / YuraCAD Solid 操作の整理（2026-10-19）

スケッチを作る操作と、スケッチから立体を作る操作を分離した。左クリックで点や位置を決め、右クリックで現在のコマンドを確定する。保存したスケッチを選んでから Extrude / Revolve / Loft / Sweep を開始し、立体のプレビューにも独立した確定・取消を設けている。

## 基本操作

| 手順 | 操作 | 結果 |
|---|---|---|
| 1 | Solid から Sketch を開始し、作業平面とペンを選ぶ | 平面上でスケッチを作成する |
| 2 | 左クリックで点・始点・終点を指定する | 矩形・円は二点で下書きができる。まだ立体を作らない |
| 3 | 幅・高さ・直径などを数値で調整し、右クリックまたは Finish Sketch | 最終寸法のスケッチを保存し、通常の選択状態に戻る |
| 4 | 保存したスケッチを選び、Extrude などの立体コマンドを選ぶ | 元のスケッチを残したまま、立体をプレビューする |
| 5 | 高さ、向き、両側、Add / Cut などを調整して右クリックまたは Confirm | 立体を確定する |

右ドラッグによる視点操作は確定として扱わない。スケッチ操作中の右クリックでは通常のコンテキストメニューを開かない。Enter でも現在のコマンドを確定できる。数値入力欄の Tab / Enter / Esc は入力欄の確定・移動・取消として処理し、背後の形状にショートカットを送らない。

スケッチを描いている途中の Esc は現在の描画を戻し、空の状態でもう一度 Esc を押すとスケッチを終了する。別コマンドとして開始した立体化の Esc はプレビューだけを取り消し、元のスケッチを残す。確定したスケッチと立体は別々の Undo ステップになる。

### 保存したスケッチの再利用

- **Edit Sketch**: 保存した閉じたスケッチを下書きとして開く。寸法や輪郭を修正し、右クリックで同じスケッチに保存する。Esc では元に戻る。名前、ID、材質などを維持する。
- **Extrude**: 高さ、Flip、Both sides を設定する。穴のあるスケッチも押し出せる。
- **Revolve**: Front / Side などの縦の平面上にある輪郭を回転する。保存前の平面原点と軸を使い、輪郭の中心に軸を勝手に移さない。
- **Loft**: Scaled copy、または別の保存済みスケッチを上側輪郭として選べる。二つのスケッチを使う場合は、平行な平面間の実距離と横方向のずれを使う。
- **Sweep**: 閉じたスケッチを断面、別の保存済み開いたスケッチを経路として選べる。開いたスケッチを直接選んで始めた場合は円形断面のチューブを作る。

第二の輪郭や経路はコマンドカードの選択欄から指定する。見つからないときは先に別のスケッチとして作成する。複数のスケッチがあるのに何も選んでいない場合、最後のスケッチを勝手に選ばない。

作成時にスケッチの形状をコピーする仕組みであり、確定済み立体を後のスケッチ編集に自動追従させる履歴・拘束ソルバーは追加していない。二つの輪郭からの Loft は平行な平面が対象で、穴の立体化は Extrude が対象となる。

## 保存・取消・入力の修正

これまでの「輪郭完成直後にガイドを保存する」経路を廃止し、明示的な確定時に保存する。これにより、矩形を作ってから数値を変えたときに、画面と保存済み輪郭の寸法が食い違う問題を防いだ。

保存データに任意の `guide_plane` を追加し、作業平面の軸と穴の輪郭を保つ。古いファイルにはこの項目がなくても読み込める。閉じたスケッチの最大64頂点を、通常の経路の48点制限で切り捨てない。既にサンプリングした円やスプラインをガイド保存時に再度滑らかにして、輪郭が変わることも防いだ。

保存コマンドは、未確定のスケッチや立体を検証してから保存する。不正な数値や未指定の Sweep 経路を無視して古い形状を保存しない。New / Open / 復旧で別の文書に切り替える前に、進行中の操作が持つ形状参照を消去し、後の Esc が新しい文書の同じ位置にある形状を削除することを防いだ。

立体プレビューや保存済みスケッチの編集では、参照している形状の位置が確定まで変わらないよう、レイヤーの並べ替え、削除、複製、貼り付け、インポートなどを一時的に無効にする。操作カードは引き続き使え、確定・取消後に通常の操作へ戻る。参照のない空の Sketch では通常の Delete を維持する。

既存の立体の輪郭を直接編集する操作では、同じ輪郭に対する Undo / Redo の後も編集を継続できる。構造が変わる操作では編集を終了し、同じ種類の形状が並んだ古いファイルでも、編集対象が別の形状に移らないようにした。ライブ形状をまだ作っていない Sweep や穴付き Extrude の設定中も、New / Open / Close の保存確認の対象に含める。

## UI と SVG

操作カードには現在のコマンド、左クリック・右クリック・Esc の役割、確定と取消を表示する。スケッチ専用インスペクターには Edit Sketch と立体化コマンドを置き、ガイドを構成する表示用の球をレイヤーに大量表示しない。

小さいウィンドウでは、カードの実測幅とツール列の位置から配置を決める。横に収まらないときはツール列の下へ移し、数値欄とボタンを折り返す。縦方向はスクロールできる。テスト用プレビューは、実際の `frame_body` と CPU 描画を使い、カードがビューポート内に収まること、ツール列に重ならないことを検査する。

ベクターアイコンは線幅、輪郭、角、矢印を整理した。線の各頂点に重ねていた円の描画を減らし、必要な鋭角だけを補正する。20種類のアイコンを68pxと34pxで描いた同じ計測では、描画用の shape 数が **1,511 → 969（35.9%減）**、頂点数が **12,928 → 10,356（19.9%減）**、三角形数が **13,701 → 12,599（8.0%減）** になった。これらはアイコン描画データの比較で、アプリ全体の FPS の計測ではない。既存のループ状 M ロゴは維持した。

SVG インポートでは次を修正した。

- root / symbol / 入れ子の SVG の viewBox、位置、拡大縮小。
- 塗りの継承、style 指定、opacity、透明な要素の扱い。
- 外周と穴をまとめて取り込む際の上限判定。穴だけを落として塗りつぶした形状を作らない。
- 再帰的な use の参照回数制限。空の要素でも展開量の増大を抑える。
- 凹形状と穴を含む色付きプレビュー。共有データとキャッシュを使い、フレームごとの大きな複製を減らす。
- モーダルダイアログ、実寸と縦横比、元のサイズ、警告、取消とインポートの表示。

SVG 仕様の全機能を実装したものではない。対応できない stroke / text / image / gradient などは警告し、扱えない複合パスは一部だけを誤った形で取り込まない。既存の SVG インポートは、今回も立体として取り込む動作を維持している。

## 軽量化

CPU の距離計算では不要な材質計算を省き、平坦なグループの一時スタック確保を減らした。多重選択では、重複確認を繰り返す線形探索と一時配列を省いた。CPU 描画の「最後のパス」と「細密描画」の判定を分け、移動中に不要な細密の陰影計算を行わないようにした。

モデル一覧のサムネイルは、生成要求と完成画像を画面の Context ごとに管理する。別の Context が画像を先に回収したために、本来の画面には画像が届かず、再要求もできなくなる競合を修正した。

20,000点の距離計算は測定したシーンで **1.16〜2.25倍**、300個の多重選択の展開は **5.11倍**になった。改善が確認できなかったケース、比較条件、旧処理との一致確認、再実行方法を含め、[軽量化の測定記録](yuracad-performance-20261019.md)に記載した。

## 検証方法

通常の回帰には左／右クリック、右ドラッグ、数値入力、Esc、Undo / Redo、保存・再読み込み、操作中のレイヤードラッグ、他の編集経路の拒否を含む。幾何の回帰には64頂点の保存、元の軸を使う Revolve、穴の両側 Extrude、二つの保存済みスケッチの Loft、保存済み経路の Sweep を含む。

通常テストは **661件成功、失敗0件、34件 ignored**。ignored は通常実行から除外されたベンチ・画像生成等を含み、全件成功したという意味ではない。今回対象の性能ベンチ3件と、実 UI / SVG / アイコンの画像生成は個別に実行した。

ローカルの検査コマンドは次のとおり。Rust 1.95.0 を使い、この環境では依存ビルドのリンカー不具合を避けるため `codegen-units=1` を指定した。これは製品のビルド設定変更ではない。

```sh
cargo +1.95.0 fmt --all -- --check
RUSTFLAGS='-C codegen-units=1' cargo +1.95.0 clippy -p meltcad --all-targets --profile ci --locked -- -D warnings
RUSTFLAGS='-C codegen-units=1' cargo +1.95.0 test -p meltcad --profile ci --locked
```

実 UI のプレビューは次のように再現できる。`YURA_SKETCH` は `draw` / `ready` / `saved` / `extrude` / `solid` / `edit` を選べる。`YURA_WIDTH=1920 YURA_HEIGHT=1080` でも同じカードの配置を確認する。
出力先の拡張子を `.png` にすると既存の PNG エンコーダーで保存する。Build CI は Ready / Extrude / Edit を両サイズで描画し、`melt3d-ui-previews` artifact に添付する。生成した画面画像をソース管理には入れない。

```sh
YURA_PREVIEW=/tmp/meltcad-ready.ppm YURA_SKETCH=ready \
YURA_WIDTH=960 YURA_HEIGHT=600 YURA_PPP=1 \
RUSTFLAGS='-C codegen-units=1' cargo +1.95.0 test -p meltcad --profile ci --locked \
app::app_preview::app_preview -- --ignored --exact --test-threads=1
```

アプリの変更と測定の基点は `integration/yuracad-20261017` の `53c487c22243c4a8c2a42720e167b7aa83015405`。作業中に追加された配布ワークフローと README の更新を含む `24486e323da507be7e74751dd97dddb7062077ec` を取り込み、その更新も維持した。既存の Build ワークフローの対象にこの統合ブランチを加え、PR の Windows / Web / テスト検査が動くようにした。Windows の対話的な実機検証は、CPU によるヘッドレス UI プレビューとは別に、既存の [Windows 受入手順](yuracad-windows-acceptance.md) で扱う。
