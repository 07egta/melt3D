# YuraCAD 操作性の比較テスト (v1)

## 実行方法

1. 比較対象の同一PC・GPU・ドライバで、ウィンドウサイズ、OS拡大率、画質、使用作品、入力機器を固定する。まず改善前ビルドで測る。**ビルドID/commit SHA** と環境を必ず記録する。
2. 「がしつ」付近の **操作性テスト** から記録画面を開き、6つのシナリオをそれぞれ選ぶ。開始前に毎回新規作品にする（再編集、変形、保存では指定の同一初期作品を使う）。
3. 改善前・改善後とも各シナリオを練習1回の後、成功回を最低5回記録する。失敗/中断回も保存して別途失敗率を確認する。計測パネルで「誤選択」と「意図しない取消」は起きたときだけボタンで明示記録する。
4. 最後に成功または失敗・中断を押す。データはOSの一時ディレクトリ内の `yuracad-ux/` に、重複上書きなしのJSONとして出力する。ファイルを直接確認して共有する。改善後も同条件、同じ作業手順と同一テストファイルにする。
5. `python apps/meltcad/scripts/compare_ux.py <両方のJSONを入れたディレクトリ>` で条件ごとの中央値、差、改善/悪化を表示する。同条件でない結果は比較しない。

## シナリオと判定

| ID | 初期状態 | 完了判定 |
|---|---|---|
| rectangle_100x50 | 新規作品・スケッチを起動 | XY上に100×50mmの四角を作り、値を確認 |
| circle_extrude | 新規作品 | 円輪郭を閉じ、押し出し形状を作成 |
| spline_node_edit | 同じ3点スプライン用初期作品 | スプラインを完成し、中央の制御点を指定位置に移す |
| transform_move_rotate_scale | 同じ箱モデル初期作品 | Xに20mm移動、Zを30度回転、1.5倍に拡大 |
| sketch_reedit | 同じ押し出し形状初期作品 | スケッチを再編集して1頂点を変更、立体へ反映 |
| save_reload | 同じ未保存作品と作業用フォルダ | 保存・再オープンし形状、色、配置の一致を確認 |

「完了」ボタンを押すのは成功条件を目視確認した後。現時点の手動レコーダーは幾何条件を自動判定しないので、テスト担当の判定が必要。開始状態、リサイズ、テストモデル、最終数値、DPIと品質を一致させない比較は無効。

## 指標の意味

- **操作数**: マウスボタンを押した回数 (ドラッグ1回=1操作)、自動リピートではないキー押下1回=1操作、ホイール200ms以内の連続操作1回。ポインター移動だけでは数えない。操作性計測パネルのクリックは対象外。テキスト入力にはIMEや貼り付けによる入力数の差がある。手動で文字列を打つ操作と比べる場合は入力方法も同一にする。
- **完了時間**: 計測開始ボタンから完了ボタンまでの実時計、秒単位のユーザー熟練差を含む。自動テストの経過時間とは比較しない。
- **誤選択/誤取消**: 意図せず発生したときだけボタンで申告する。Esc、Undo、選択変更だけで自動計上しない。
- **UI FPS/UI p95**: 入力活動のあるegui UIフレーム間隔 (250ms以上の無活動ギャップ除外) から算出する参考値。画面表示の実FPSではない。
- **UI CPU p95**: Rust側の `frame_body` 呼び出し中のCPU処理時間のp95。GPU処理時間、OS画面表示時間ではない。
- **入力→画面反映遅延**: **未測定**。入力時刻とディスプレイpresentation/光学映像のタイムスタンプが必要。eguiのフレーム終了までの時間を代わりに使わない。
- **ディスプレイFPS**: **未測定**。本当に表示されたフレームはPresentMon等の外部計測ツールで別途測る。既存のF3/--benchは他の描画性能監査として利用できるが、この6つの人間作業の表示FPSとは混ぜない。
- 記録サンプルが5件に満たないp95/FPSは未測定。異なるPC、DPI、ウィンドウサイズ、GPU、画質、OS、テストデータを混ぜない。

## 自動回帰との分離

- `cargo test -p meltcad ux_bench -- --nocapture`: 6つのシナリオID、アクション単位、サンプルのp95、誤操作の明示申告、未測定フィールドが `null` であることを検査。**UI操作全体が成功するテストではない**。
- `cargo test -p meltcad input_tests`: マウスイベントを `App::viewport` に渡す既存の入力回帰テスト。
- `cargo test -p meltcad frame_bench`: eguiフレーム本体のCPU回帰。無視指定の実測ベンチは `cargo test -p meltcad --release frame_cpu_bench -- --ignored --nocapture`。
- `meltcad --bench [out.txt]`: 既存のオフスクリーンGPU描画速度。実アプリのタスク完了時間を意味しない。

## 判定の優先順位

最優先は「成功率を下げずに操作数、誤操作率、p95入力処理の低減」。改善前後の成功率、操作数、完了時間の中央値を見て優先する。フレーム時間p95やFPSの改善だけでは、使いやすさの向上と判定しない。実測不能な指標は数値を捏造せず未測定とする。

## 検証状態

この計測基盤のコードはブランチ上に追加した。CIがGitHub Actionsの利用制限で止まる可能性があり、Windows実機での手動測定結果はまだない。自動テストの成功が確認できるまで「動作確認済み」としない。
